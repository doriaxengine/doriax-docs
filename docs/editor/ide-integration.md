# IDE Integration

The built-in [Code Editor](code-editor.md) is where scripts open by default. A Doriax
project also opens in VS Code, Visual Studio, CLion, or any editor with a C++ and a Lua
language server. The editor writes the files those tools read, so C++ and Lua scripts get
completion, documentation on hover, go to definition and find references, and C++ scripts
can be debugged with breakpoints, variables and call stacks while the scene plays in the
editor.

## Choosing a script editor

**Edit → [Editor Settings](editor-settings.md#general) → General → Script Editor** picks
where scripts open:

| Choice | Opens with |
| --- | --- |
| **Built-in Editor** | The [Code Editor](code-editor.md), the default |
| **VS Code** | `code`, from `PATH` or the usual install folders |
| **Visual Studio** | `devenv.exe` of the newest Visual Studio, not Build Tools (Windows) |
| **CLion** | On Windows `clion64.exe` on `PATH`, the JetBrains Toolbox script, or the newest install. Elsewhere the `clion` launcher, or the app on macOS |
| **Custom Command** | A command line you write, see below |

The choice applies to Lua and C++ files (`.lua`, `.h`, `.hpp`, `.cpp` and similar):
a double click in [Resources](resources.md), the script buttons in
[Properties](properties.md), and the file links in the Output panel. Shaders and other
text files stay in the built-in editor. With an IDE chosen, the right-click menu of a
script in Resources keeps **Open in Built-in Editor**.

**Project → Open in VS Code** (named after your choice) writes the project's IDE files,
described below, and opens the project folder in the IDE.

A **Custom Command** runs through the system shell, with `{project}`, `{file}`, `{line}`
and `{column}` replaced; paths come quoted. For example:

```text
subl {file}:{line}:{column}
```

## Links in Output

Compiler errors, Lua errors and stack traces name a file and a line. In the Output panel
those locations are underlined when the pointer is on them: **Ctrl+Click** opens the file
at that line in the script editor, as does **Open** in the right-click menu. The editor
reads the formats of GCC and Clang (`file:line:column:`), MSVC (`file(line,column):`) and
Lua (`[string "scripts/Player.lua"]:12:`). Only files that exist are links.

## Files the editor writes

| File | Used by |
| --- | --- |
| `.vscode/c_cpp_properties.json` | The C/C++ extension: the compile commands of the last build, and the include paths and defines until there are any |
| `.vscode/settings.json` | CMake Tools and clangd, and YAML highlighting for `.scene` and `.bundle` files |
| `.vscode/extensions.json` | The recommended extensions: C/C++, CMake Tools and Lua |
| `.vscode/tasks.json` | **Doriax: Build Project**, the standalone build of the preset |
| `.vscode/launch.json` | The [debug configurations](#debugging-c-scripts) |
| `CMakeUserPresets.json` | The `doriax` preset of Visual Studio, CLion and CMake Tools: the standalone build with the editor's compiler and build type |
| `.luarc.json` | lua-language-server: Lua 5.5, the `require` paths, and the definitions below |
| `.doriax/engine-api/lua-api/doriax.lua` | Definitions of the engine's Lua API |
| `.doriax/lua-api/scripts.lua` | The properties of each Lua script |
| `.doriax/compile_commands.json` | Compile commands of the last build, from Play or the preset |

They are written when the project is saved, when a scene plays, by **Project → Open in…**,
and by [`doriax-editor ide`](command-line.md#ide-write-the-ide-files) without a window.
Each `.vscode` file starts with this line:

```text
// Generated by Doriax Editor. Delete this line to keep your own changes.
```

`CMakeUserPresets.json` and `.luarc.json` are plain JSON, so their marker is the
`"doriax-editor"` entry instead. While the marker is there the editor keeps the file up to
date; delete it and the editor leaves the file alone from then on. A
`.vscode/settings.json` written by an older editor has no marker, so delete it once to get
the new one.

`.vscode/` and `CMakeUserPresets.json` hold paths of your machine and the generated
`.gitignore` leaves them out. `.luarc.json` has none, so commit it with the project. See
[Version Control](version-control.md).

## C++ scripts

Each build, from Play or from the preset in an IDE, copies its `compile_commands.json` to
`.doriax`, where the C/C++ extension and clangd read it, so completion and errors follow
the real build. Until the first build, and with the Visual Studio generator, which writes
none, the include paths and defines of `c_cpp_properties.json` stand in.

- **VS Code**: open the project folder and install the recommended extensions.
- **Visual Studio**: turn on **Tools → Options → CMake → General → Use CMakePresets.json**,
  since Visual Studio reads `CMakeUserPresets.json` only with it, then **File → Open →
  Folder** and pick the `doriax` configure preset. Its own default preset builds `Debug`.
- **CLion**: open the folder and enable the `doriax` profile under **Settings → Build,
  Execution, Deployment → CMake**.

The engine headers in `.doriax/engine-api` carry the descriptions of the
[API reference](../reference/index.md) as `///` comments, so a hover over an engine class
or method shows them, and go to definition lands on the documented declaration. An editor
built from source has the descriptions when the `doriax-docs` repository is checked out
beside `doriax`, or where `DORIAX_DOCS_DIR` points.

Play builds the scripts as a library the editor loads, in `.doriax/build`. The preset
builds the project as an executable of its own, in `.doriax/externalbuild`, linking the
editor's engine library. Its build type is the editor's, `Release` for a release editor,
and should stay so: scripts built as `Debug` do not match the engine library.

## Debugging C++ scripts

**Editor Settings → [Desktop](editor-settings.md#desktop) → Debug Info** sets what the
scripts are built with, for Play and for the preset:

| Debug Info | Effect |
| --- | --- |
| **None** | No debug information |
| **Symbols** | The default. Breakpoints and call stacks work; the code stays optimized, so some variables read as optimized out and stepping can jump |
| **Symbols, No Optimization** | Exact stepping and variables, slower scripts |

`.vscode/launch.json` has three configurations of the C/C++ extension (gdb on Linux and
for MinGW builds, lldb on macOS, the Visual Studio debugger for MSVC builds):

| Configuration | Does |
| --- | --- |
| **Attach to Doriax Editor** | Attaches to a running editor: pick `doriax-editor` in the list. Breakpoints in scripts stop the scene while it plays |
| **Doriax Editor** | Starts the editor on this project under the debugger, as `doriax-editor --project <folder>` |
| **Run Project** | Builds the preset and runs the project on its own |

In Visual Studio, use **Debug → Attach to Process** and pick `doriax-editor.exe`, or
select the project's executable in the startup item list to debug the standalone build. In
CLion, use **Run → Attach to Process**.

A breakpoint set before Play stays pending until the editor loads the script library, and
it holds across rebuilds: each Play loads a new copy of the library. On Linux the default
`ptrace_scope` of most distributions refuses a debugger that did not start the process, so
the editor lets one of the same user attach, unless **Debug Info** is **None**. On Windows a debugger keeps the PDB it loaded open,
so while one does, the next Play links the scripts under a new PDB name.

Lua scripts have no breakpoints yet: use `Log.print` and the links in Output.

## Lua scripts

[lua-language-server](https://luals.github.io/), the Lua extension of VS Code
(`sumneko.lua`), reads `.luarc.json`. The engine's classes, enums, events and global
functions are typed, with the reference descriptions on hover, so completion, go to
definition and type checks work across the API. An event such as `Engine.onUpdate` takes a
function, or `add` and `call` on it. It needs version 3.16 or newer, the first with Lua 5.5.

A script the editor creates starts with a class annotation:

```lua
---@class Player: LuaScript
local Player = {
    properties = {
        { name = "speed", displayName = "Speed", type = "float", default = 5.0 }
    }
}
```

It makes `self` a `Player` in its methods: `self.scene` and `self.entity` come from
`LuaScript`, and `self.speed` from `.doriax/lua-api/scripts.lua`, which the editor
rewrites from each script's `properties` table. Add the line above the table of an older
script to type it too. A property whose type names an engine class, such as `Object`, or
another script's class is typed as that class.

`require` resolves as in the engine: a module from the Lua folder, or from its `lua/`
subfolder.
